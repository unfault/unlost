Install

Get Unlost

curl -fsSL https://unlost.unfault.dev/install.sh | bash
For Windows, please download the binary from our releases page.

Agent Integration

Hook unlost into your agent. Choose global for system-wide coverage, or per-project for opt-in control. 

# Claude Code - one command, works everywhere
unlost config agent claudecode --global

# OpenCode - opt-in per repository
cd your-project
unlost config agent opencode --path .
If you want to use Unlost with your favourite agent, please drop us a note.

Configure Your LLM

Unlost requires an LLM for capsule extraction and summarization. While friction detection works locally, a dedicated extraction model dramatically improves capsule quality. Better structured data means more accurate recall and sharper pattern detection. 

unlost config llm anthropic --model claude-sonnet-4-5-20250929
unlost config llm openai --model gpt-4o-mini
Recommendation: Use a fast, cheap model like GPT-4o-mini or Claude 3.5 Haiku. Extraction doesn't need reasoning; just structured output. You'll process thousands of messages; speed and cost matter more than intelligence.

That's it. Next time you start your agent, unlost will automatically work alongside it. Happy coding!

How It Works

01

Intercept & Record

Hooks into agent events and writes everything to an append-only JSONL journal. Non-blocking; returns immediately while processing continues in the background.

# Journal entry
{timestamp: "2025-02-09T14:23:00Z", event: "message", role: "assistant", content: "..."}
02

Summarize & Store

LLM extracts structured capsules (intent, decision, rationale, next_steps). FastEmbed generates local embeddings. Everything stored in LanceDB; no data leaves your machine.

# Capsule + embedding
{intent: "Fix auth", decision: "Use middleware", rationale: "...", embedding: [0.23, -0.45, ...]}
03

Friction & Failure Mode Detection

Analyzes conversation patterns in real-time: drift, retry spirals, false progress, unbounded horizons. Detects when the agent is about to go off the rails.

# Friction detected
retry spiral after 3 failed attempts
pattern: "The Apology Loop" | confidence: 0.87
04

Injection Decision

Automatic intervention when friction is detected. Injects contextual guidance into the conversation before the agent sends its next prompt. No manual intervention.

# System message injected
[SYSTEM: You've attempted this fix 3 times. Consider a different approach.]
05

Recall & Query

Async semantic search across your workspace memory. Query by natural language, symbols, or file paths. Returns relevant capsules with context; why did we do X?

# User query
$ unlost query "why did we switch to postgres?"
# Result
→ Found: 3 capsules | Intent: "Improve analytics performance"

The Components of Unlost

Capsule Memory

Structured, searchable records of agent conversations. Each capsule captures intent, decisions, rationale, and next steps—building a persistent memory layer for your codebase.

# Example capsule
chunked_at: 2026-02-13T14:47:31Z
session: ses_3a887ec6effeHddMqe9691wY6V
conn: 5 seq: 1 status: 200
category: repo_exploration
intent: Thoroughly explore the codebase to learn what Unlost does...
decision: Proceed to review README, main configuration files...
rationale: The user explicitly requested a deep codebase review...
next: ["Open README and main configuration files...", ...]
symbols: ["README", "Claude"]

Facts and Metadata We Store

Beyond raw text, we extract and index key entities that enable precise semantic search and context-aware recall:

  • Symbols: Functions, classes, variables, and code identifiers mentioned in conversations
  • Files: File paths and references to help locate where changes occurred
  • Technologies: Frameworks, libraries, and tools being used or discussed
  • People: User mentions and agent identities for accountability tracking
  • Relationships: Links between entities (e.g., which function belongs to which file)
  • Session context: Connection IDs, sequence numbers, and temporal metadata

Unlost uses this metadata to build a knowledge graph that powers targeted queries. When you search for "auth flow", we don't just match text—we understand which files and symbols are involved, enabling you to ask precise questions like "what changed in the auth middleware last week?"

Emotions

We analyze conversation patterns to detect emotional signals that indicate when interactions may be deteriorating:

  • Valence: Positive vs negative sentiment (-1.0 to +1.0)
  • Intensity: Strength of the emotional response (0.0 to 1.0)
  • Confidence: Certainty in the emotional classification (0.0 to 1.0)

The purpose is early detection of friction before it escalates. When emotion signals cross thresholds, Unlost can intervene with guidance or escalate to the user.

# Emotion detection example
user_mood: frustration (conf=0.55 val=-0.50 int=0.45)
# Detected from patterns like:
- "That didn't work" followed by multiple retries
- Increased negative language density
- Repeated similar prompts with escalating tone

Frictions We Compute

Real-time detection of failure patterns computed locally to identify when agents are about to go off track:

1. Drift Detection

Measures semantic divergence between the original intent and current conversation trajectory. When the agent's focus shifts away from the stated goal beyond a threshold, we flag potential drift.

2. Retry Spiral

Detects repeated attempts to solve the same problem with similar approaches. Algorithm: track consecutive failures on the same task, increment counter on each retry, flag when exceeding threshold (typically 3+ attempts).

3. False Progress

Identifies when the agent reports success but metrics don't improve. We compare claimed outcomes against actual test results, build status, or lint errors to detect phantom progress.

4. Unbounded Horizon

Flags when the scope of work expands uncontrollably. Algorithm: monitor the number of files touched, new dependencies introduced, or architectural changes—trigger when growth exceeds 2x the original scope estimate.

# Friction detection in action
retry spiral detected: 4 consecutive failures on auth fix
confidence: 0.87 | pattern: "The Apology Loop"
→ Injecting guidance: "Consider reviewing the middleware order"

Recall & Query

Semantic search across your workspace memory to retrieve relevant context and answer questions about past work.

How Recall Works

Recall generates a proactive overview by aggregating recent capsules relevant to a specific file or directory.

  • Path matching: Filter capsules by file/directory path
  • Recency weighting: Prioritize more recent interactions
  • Depth control: Limit how many capsule layers to traverse
  • Summarization: LLM synthesizes filtered capsules into coherent context

How Query Works

Natural language search converts your question into embeddings and performs semantic similarity matching.

  • Embedding: Your query is converted to a vector using the same model that indexed the capsules
  • Vector search: LanceDB performs approximate nearest neighbor (ANN) search across all capsule embeddings
  • Hybrid scoring: Combines semantic similarity with metadata filters (time range, symbols, files)
  • Relevance ranking: Results sorted by similarity score, with option to limit count
  • Context assembly: Top-k capsules are returned with their full metadata for LLM context injection
# Recall operation
$ unlost recall src/auth.rs --depth 3
→ Found 12 capsules | Generating summary...
→ Last modified: JWT middleware, token validation, error handling
# Query operation
$ unlost query "why did we add rate limiting?"
→ ANN search: 0.023s | 47 capsules scanned
→ Top match: "Prevent API abuse" (score: 0.89)
→ Related: auth middleware, redis cache, 429 responses
